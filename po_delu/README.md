# По делу

Редактор русских документов. Сначала откройте текст или файл, при необходимости уточните аудиторию и задачу и запустите поиск. У каждой находки есть исходная цитата, место, объяснение и контекст. Откройте нужную находку, выберите её, задайте стиль и ограничения и запросите замену. Сравните исходник и предложение перед экспортом. Список замечаний можно скачать отдельно.

## Форматы

Поддерживаются ввод с клавиатуры, UTF-8 TXT, Markdown, HTML, DOCX, PPTX и PDF с текстовым слоем. HTML разбирается как документ: сценарии и обработчики страницы не исполняются. В поддерживаемых HTML-узлах при экспорте меняется только выбранный текст. Для PPTX доступны номер слайда, фигура, предпросмотр и проверка совместного размещения правок в режиме «Вписать в рамку». Для сложных PDF используйте аннотации или текстовый экспорт. Сервис проверяет текст презентации; выводы о композиции или авторстве в результат не входят.

## Локальный запуск

Приложение проверено с Python 3.11 и в образе Python 3.12. Для рендера презентаций нужны LibreOffice Impress и кириллические шрифты. В Docker они включены в образ. Команды ниже выполняются в каталоге с этим файлом.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
PO_DELU_REQUIRE_MODEL_CONSENT=1 .venv/bin/uvicorn web:app --host 127.0.0.1 --port 8000
```

Страница открывается по адресу http://127.0.0.1:8000. Для запуска в контейнере выполните следующие команды.

```bash
docker build -t po-delu .
docker run --rm -p 127.0.0.1:8000:8000 \
  -e PO_DELU_REQUIRE_MODEL_CONSENT=1 \
  -v po-delu-memory:/home/editor/.local/share/po-delu po-delu
```

## Поиск и проверка моделями

Локальный режим проверяет ограниченный набор оборотов и точные совпадения с личными примерами. Для модельного режима задайте переменные процесса из .env.example. Настройки семантического поиска — LLM_BASE_URL, LLM_API_KEY и LLM_MODEL. EDITOR_DETECTOR выбирает semantic, slopotron, union или однопроходный baseline. В union доступны кандидаты обоих каналов. Для провайдера с поддержкой инструментов EDITOR_SEARCH_PROTOCOL=mcp включает вызовы чтения и привязки самой моделью. JSON-профиль поддерживает модели без native tool calling.

EDITOR_JUDGES_JSON задаёт отдельные модельные семейства. Каждый судья получает источник и цитату без названия поискового канала и чужих ответов. Нужны не менее двух независимых семейств и абсолютное большинство настроенной панели. Голоса должны иметь проверяемые опоры в тексте. При недоступности кворума сервис сохраняет причину, спорный кандидат остаётся без автоматической правки. После генерации контролёр проверяет факты, силу обязательств и границы изменения. EDITOR_FIDELITY_CONSENSUS=1 включает отдельное голосование разных семейств по самой замене. Нужны как минимум два подтверждения; явный отказ блокирует вариант. В профиле serve_loopback.py этот режим включён. В отчёте вызовов видны модель, ошибки, охват и usage, если его вернул провайдер.

Рабочий профиль с OpenRouter в serve_loopback.py использует ключ из файла с ограниченными правами, согласие на передачу каждого документа и общий SQLite-учёт расходов. PO_DELU_BUDGET_DB указывает на постоянный журнал, PO_DELU_KEY_FILE — на файл ключа. Лимит профиля составляет 9,50 USD на журнал, включая зарезервированные вызовы с неизвестной стоимостью. Профиль предназначен для ограниченного локального доступа. Не создавайте новый журнал для обхода лимита. Для собственного внутреннего endpoint можно использовать обычный запуск с .env.example.

## Редактура и память

Находки и авторские предпочтения отображаются отдельно. Добавьте пример «было → предпочитаю» или исключение «оставить», при желании запишите объяснение. При следующем открытии в том же профиле браузера точное совпадение находится локально. Модельный поиск похожих конструкций и передача личных примеров редактору требуют отдельного выбора. Правила можно просматривать и удалять. Хранилище SQLite задаётся через PO_DELU_MEMORY_DB, по умолчанию используется ~/.local/share/po-delu/preferences.sqlite3. Профиль браузера определяется случайной HttpOnly cookie; очистка cookie прерывает привязку к прежней памяти. Профили бота и веба разделены.

Для правки можно сохранить голос, перейти к прямому, юридически формальному или дружескому изложению. Задайте дословные якоря, границы и допустимую длину. Несколько выбранных мест одного абзаца проверяются вместе и экспортируются одной заменой блока. При смене оригинала или конфликте ограничений нужна новая проверка. Сессия документа временная, личные правила сохраняются между сессиями.

## Telegram и проверки

Для приватного бота с теми же настройками требуется TELEGRAM_BOT_TOKEN. Запуск — python bot.py. Отправьте документ или сообщение. Используйте /finding, /report, /marked для разбора и /rewrite, /show, /save для предложений и выгрузки. Для памяти предусмотрены /example, /except, /memory и /forget. Команда /models once разрешает модельный режим для следующего документа, /similar on и /share on отдельно включают использование личных примеров. Сценарии бота проверены на тестовом транспорте.

Запускайте тесты командой python -m unittest discover -s tests -v. Для браузерной проверки есть tests/browser_smoke.py. Архив исходного стартера хранится в корне комплекта. Контрольные материалы и экспертные ответы лежат вне приложения.

## Этот рабочий хост

Основной адрес — http://127.0.0.1:18477/. Имя профиля моделей и общий журнал расходов задаёт serve_loopback.py. Процесс работает в среде, из которой OpenRouter доступен. Если он остановлен, из корня комплекта выполните:

```bash
python3 tools/start_workspace.py --state /home/firsov/.local/share/po-delu \
  --renderer-cache /home/firsov/.cache/agm-docs-v208
```

Резервный автономный экземпляр po-delu-offline доступен на порту 18476 хоста и использует постоянный том для личных правил. Публикация обоих адресов ограничена loopback. Для своего рабочего компьютера можно пробросить основной порт через обычное разрешённое SSH-подключение: ssh -N -L 18477:127.0.0.1:18477 ИМЯ_ХОСТА. После этого открывайте основной адрес в браузере на своём компьютере.
