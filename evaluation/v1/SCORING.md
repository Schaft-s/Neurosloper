# Как считать поиск и редакторские вердикты

Из корня комплекта запустите две команды. Вторая команда читает сохранённые JSONL локально, учитывает все подходящие конфигурации под `evaluation/v1/runs` и записывает сводку в указанный каталог. Параметр `--run NAME` можно повторять для сопоставления выбранных запусков.

```bash
python3 -m unittest discover -s tools/tests -p test_score_benchmark.py
python3 tools/score_benchmark.py --out evaluation/v1/scores --bootstrap 1000 --seed 71129
```

[Внутренний каталог](Каталог.html) открывается как локальный HTML-файл. Команда `python3 tools/browse_eval.py` собирает в нём исходные тексты, решения, разборы реальных правок и доступные результаты замен из `scores/rewrite.csv`. Выполните её после обновления оценок редактуры. В каталоге есть восемь отдельных переключателей слоёв и поиск по содержимому. Для двух исключённых жанровых документов присутствуют только карточки исключения. У исторических отзывов выделено возможное место возражения там, где оно однозначно найдено. Вердикт о границах этому выделению не присваивается.

Единица проверки — задокументированная версия файла. Сверяются SHA-256 текста, ревизия предсказания, смещения непустых строк и буквальные цитаты. Начало входит в интервал, конец исключён. Строки, в том числе повторные, располагаются по координатам исходника. Если эталон пересекает перевод строки, его длина и границы сохраняются. Пример с двумя системами перевода строк и кодовой точкой вне BMP есть в тестах.

## Поиск

Максимальное число взаимно однозначных пар находится увеличивающими путями в двудольном графе. Основное ребро требует IoU ≥ 0,5. Дополнительно считаются точное равенство интервалов и пересечение хотя бы в одной кодовой точке. Соседние полуоткрытые интервалы имеют нулевое пересечение. При нескольких максимумах порядок детерминирован, отдельная выбранная пара может меняться при перестановке одинаковых предсказаний. Совпадающие границы сырых поисковых предложений нескольких каналов объединяются. Дубли уже выданной находки остаются отдельными предсказаниями.

- `proposals.csv` измеряет места до решения судей. `candidate_iou50_recall` показывает долю найденных положительных эталонных мест. `search_missed` считает места, для которых не хватило однозначных соответствий. В `search_complete` входят документы с полным охватом запрошенных поисковых каналов и без зарегистрированных ошибок поиска. Для одношагового режима и локальных правил доступен счётчик посещённых блоков. Для региональных каналов проверяются также покрытые символы внутри каждого блока.
- `detection.csv` измеряет доставленные `flag`. `fp` и `fn` относятся к однозначным соответствиям с эталонами `flag`. `filter_missed` — разность между числом доступных до фильтра и подтверждённых совпадений. Она включает объединение кандидатов и потерю кворума. Ненулевые сопоставления с эталонами `uncertain` показаны отдельно. `clean_false_alarm_rate` вычисляется только на документах с эталонным решением `keep`.
- `complete` ограничивает показатели полностью сработавшим конвейером. `end_to_end` оставляет все ID из конфигурации, в том числе ещё не появившиеся в JSONL и вернувшие ошибку. Сохраняется действительная доставленная находка даже при частичном просмотре. Пустой технический результат получает `unavailable` на уровне документа. При успешной проверке документ получает `flag`, если показана хотя бы одна находка, затем `uncertain` при действительном воздержании и `keep` для чистого выхода. Список ID вне конфигурации приведён в `summary.json`.
- У локального поиска без независимого кворума основная метрика — `proposals.csv`. Результат интерфейса виден отдельно в `detection.csv` в строках `end_to_end`. Техническая недоступность решения и осознанное воздержание судьи имеют разные значения. `documents.csv` и `locations.csv` показывают, где возникли лишние и пропущенные интервалы. У `locations.csv` статус относится ко всему конвейеру; состояние самого поиска доступно в `documents.csv`.

## Контрасты и согласие

`ballots.csv` содержит каждый зафиксированный вердикт на предложенном месте и каждый индивидуальный бюллетень, включая технические отказы. Сохранённый кворум и решение перепроверяются подсчётом голосов различных действительных семейств. `judge_agreement.csv` даёт парное согласие и каппу на одних и тех же местах с двумя действительными ответами. Технический знаменатель виден в `offered`, а фактическая совместная доступность — в `both_available`.

В `target_decisions.csv` свободный поиск сопоставляется с заданным местом по IoU ≥ 0,5. При полностью сработавшем поиске отсутствие предложения на этом месте означает, что пользователь не увидит для него флаг. Для заданного места в режиме fixed проверяется точное соответствие цитаты, блока и абсолютных границ. В `target_scores.csv` результат по всем запланированным ID отделён от результата по найденным местам с действительным решением. Строка `both_correct` требует правильного решения на обеих половинах семьи. `decisive_flip` включает и перепутанное направление, для которого дан отдельный счётчик `reversed`.

Согласие двух независимых модельных редакторов по всем 90 жанровым документам хранится отдельно в `summary.json` и `annotations.csv`. Даны трёхклассовая таблица, доля равных решений, каппа Коэна и совпадение границ по типу решения. Поиск оценивается раздельно относительно каждого редактора и, если предоставлена, согласованной разметки. Для внешнего набора оцениваются только опубликованные выдержки. Каждая исходная страница даёт одну пару версий. О редакторских предпочтениях и границах источника см. [EXTERNAL.md](EXTERNAL.md).

## Интервалы и пропуски

Для перспективного набора `lockbox` оценщик подключает отдельную разметку при наличии файлов `evaluation/lockbox/{inputs,keys,targets}.jsonl`. Общность сценария проверяется по структуре пар и троек. Между `group` и `family` выбирается столбец, который связывает больше вариантов одного сценария с разными решениями; при равенстве учитывается сохранение цитаты между вариантами. У подготовленного набора это `group`. Предсказания судей сравниваются с тремя возможными решениями. В `target_scores.csv` столбец `both_correct` требует правильных ответов на определённой положительной и отрицательной версиях. `all_versions_correct` требует верного ответа на всех версиях сценария, включая неопределённую, когда она есть. `three_way_groups_correct` отдельно считает полностью верные тройки. Неполные по конфигурации группы в этот знаменатель не входят. Для свободного поиска в `detection.csv` приведены полнота и точность для каждого из трёх документных решений. Техническая недоступность остаётся четвёртой, ошибочной выходной категорией.

Для основных метрик применяется 95% процентильный bootstrap. Будущая выборка моделируется повторным выбором исходных документов с возвращением. Половины контраста и редакции одной внешней страницы сохраняются в одном кластере. Для разности методов в `paired_methods.csv` оба метода получают одни и те же выбранные ID. Знак разности — показатель правого метода минус показатель левого. Реплики с нулевым знаменателем пропускаются только для соответствующей метрики; число определённых реплик записано рядом с интервалом. Отсутствующий знаменатель даёт JSON `null` или пустую ячейку CSV. Пустое значение F1 при отсутствии находок и положительных эталонов отличается от нулевого F1 при реальных пропусках.

Конфигурация задаёт плановое число документов, текущие файлы предсказаний — доступный результат. Повтор команды во время дозаписи даст другой срез. Для воспроизведения окончательной цифры используйте одни и те же зафиксированные файлы предсказаний, ключей и конфигураций. Оценщик не использует модель, не отправляет тексты и не изменяет предсказания.
