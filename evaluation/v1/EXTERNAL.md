# Русские технические документы до и после опубликованной правки

В выборке 15 пар из 15 разных страниц. Восемь пар взяты из русской версии MDN Web Docs, семь — из русской документации React. Каждый отрывок дословно взят из Git. До правки контекстуальная оценка дала 12 решений `keep`, два `flag` и одно `uncertain`. После правки — 12 `keep` и три `flag`. Повторно посчитанные версии одного отрывка остаются зависимыми наблюдениями. [Данные](external.jsonl)

## Как отбирались пары

Для MDN рассматривались последние 85 коммитов по каталогу `files/ru` на момент выборки 25 ноября 2026 года. Вручную открывались изменения, в названии которых упомянута русская правка примера, описания, перевода или опечатки. В истории React просматривались коммиты с сообщениями о правках по итогам рецензирования и применении предложений рецензента. Для каждой выбранной страницы читались изменённый фрагмент, окружающий раздел и соответствующая родительская версия. Из длинных абзацев взята одна непрерывная выдержка. Служебные строки и одинаковые повторения по нескольким страницам пропускались. Среди подходящих случаев оставлялись различные читательские задачи, включая переход по ссылке, чтение заголовка, проверку результата программы и разбор противопоставления в учебнике. Отбор целевой, без квоты на находки.

Исходное и принятое в проекте чтения подтверждаются Git. В 13 из 15 pull requests есть публичное одобрение рецензента. У `ext-05` и `ext-06` есть автор и соавтор коммита, но API не вернул публичного отзыва для соответствующего PR. Поле `reviews` содержит отдельные события рецензирования всего PR. Подпись или одобрение не раскрывает, кто предложил каждое слово, что именно предпочёл рецензент и какими средствами он пользовался. Имена, сообщения и ссылки сохранены в данных.

Новые для комплекта источники меняют сразу несколько условий: предмет, жанр, наличие контекста статьи и характер правки. Это позволяет проверять отдельные ложные срабатывания на документации. Пятнадцати редакционных пар из двух проектов недостаточно для оценки частоты шаблонных подмен в русских текстах, а публичность материалов допускает их присутствие в предобучении.

## Смысл полей

- `scope=partial_pair` ограничивает оценку одним опубликованным отрывком в двух версиях. `function_brief` и `context` составлены рецензентом по назначению раздела. Это контекст для оценки, а не цитаты из редакторского задания.
- В `before` и `after` лежат неизменённые выдержки в исходной разметке Markdown. Их координаты в декодированном файле UTF-8 указаны в `start_in_file` и `end_in_file`. Координаты `spans` отсчитываются от начала выдержки. В обоих случаях считаются кодовые точки Unicode, левая граница включена, правая исключена. `file_sha256` вычислен от байтов файла, `text_sha256` — от UTF-8 выдержки.
- `decision` отмечает только наблюдаемый шаблон, подменяющий выбор выражения для этой задачи. `keep` допускает ошибку в фактах, орфографии или грамматике. `uncertain` означает, что обычное объяснение приёма нельзя разрешить по доступному контексту.
- `preference` — оценка одного модельного рецензента по пригодности выдержки для читателя, с учётом смысла и языка. В десяти парах выбрана поздняя версия, в одной — ранняя, три дали `either`, одна — `neither`. Поле `reason` поясняет выбор, `normal` рассматривает обычное объяснение. Предпочтения сформированы с известной хронологией и могут служить материалом для независимой перепроверки. Историческая запись выбора между двумя ослеплёнными вариантами отсутствует.
- При оценке детектора подавайте одну выдержку, её функцию и контекст. При слепом сравнении независимо перемешивайте две версии, сохраняя ориентацию для подсчёта. Служебные поля с источником, изменением и решением показывайте после ответа. Считайте по `id`, публикуйте сырые числа и отдельно долю отказов от решения. Пример `ext-02` сохраняет риторическую формулу после исправления опечаток. В `ext-13` она появляется в поздней версии.

## Воспроизведение

Из корня комплекта можно заново получить все 30 файлов по неизменяемым Git SHA, сверить контрольные суммы, цитаты, координаты, номера строк и связь коммита с первым родителем. Скрипт передаёт в GitHub только публичные имена исходных файлов и коммитов.

```bash
python3 - <<'PY'
import hashlib
import json
from pathlib import Path
from urllib.parse import quote
from urllib.request import Request, urlopen

def fetch(url):
    request = Request(url, headers={"User-Agent": "ru-editorial-pair-verification"})
    with urlopen(request, timeout=30) as source:
        return source.read()

def digest(data):
    return hashlib.sha256(data).hexdigest()

rows = [json.loads(line) for line in Path("evaluation/v1/external.jsonl").read_text().splitlines()]
assert len(rows) == len({row["id"] for row in rows}) == 15
for row in rows:
    repo = row["repository"]
    commit = row["after"]["sha"]
    info = json.loads(fetch(f"https://api.github.com/repos/{repo}/git/commits/{commit}"))
    assert info["parents"][0]["sha"] == row["before"]["sha"]
    for side in ("before", "after"):
        part = row[side]
        path = quote(row["path"], safe="/")
        raw = fetch(f"https://raw.githubusercontent.com/{repo}/{part['sha']}/{path}")
        source = raw.decode("utf-8")
        start, end = part["start_in_file"], part["end_in_file"]
        assert digest(raw) == part["file_sha256"]
        assert source[start:end] == part["text"]
        assert digest(part["text"].encode()) == part["text_sha256"]
        assert source[:start].count("\n") + 1 == part["line"]
        for span in part["spans"]:
            assert part["text"][span["start"]:span["end"]] == span["quote"]
print(f"Проверены {len(rows)} пар и {2 * len(rows)} выдержек.")
PY
```
