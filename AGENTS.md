# Задание для агента разработки

Стартовая реализация в po_delu_starter.zip, исходные входы веба и бота описаны в её README. Новая спецификация — PROJECT.md. Этот файл и PROJECT.md имеют приоритет над старым планом внутри стартера. Сначала воспроизведите его штатные тесты и проверьте, что умеет реальный endpoint с tool calling. Не вытесняйте работающие экспорты исследовательским кодом. Внешний model API и рабочие документы использовать только в согласованном контуре.

1. В engine.py отделите предложение кандидатов от их проверки. Оставьте переключаемый одношаговый режим для честного baseline. Не полагайтесь на наличие Слопотрона или Qwen при старте. Введите регион документа, контекстные связи, защищённые участки, версию оригинала и воспроизводимую трассу. Внешние инструкции и модели подключайте по ревизии.
2. Подключите Detect как альтернативный источник, матчите цитату с исходником, не выдавайте ошибку привязки за keep. Сравните две стратегии поиска и объединение. Сохраните процент документов без замечаний, пропуски до фильтра, ложные срабатывания после него и цену каждого канала. Решение об эксплуатации принимать по результату, включая длинные и юридически формальные документы.
3. Реализуйте в обоих интерфейсах четыре регистра, допускаемые интервалы, дословную защиту и режим длины отдельными полями. У генератора сменная модель, у верификатора отдельный контекст с исходником. Используйте data/fidelity_keys.jsonl для критических ошибок, включая перестановку чисел. Отсутствие замены с причиной — корректный исход. Не настраивайте детектор под выбранный будущий регистр.
4. Перепроверьте изменения в docx/pptx/pdf через штатные входы. Отдельно проверяйте сохранность соседних блоков, несколькo выбранных правок в одной рамке, ошибки привязки и изменение документа между просмотром и экспортом. Не допускайте автоматической публикации файла или применения неподтверждённого изменения.
5. Выполните сравнение в PROJECT.md. Фиксируйте конфиг, ревизию, входной хеш, этап, tokens, elapsed, тип сбоя. Разработчику показывают dev, оценщику — отдельные референсы, модели — только вход. Выводы прежних исследований в evaluation/; эти наборы уже раскрыты.
6. Перед сдачей откройте размещённый сервис по реальной ссылке, напишите боту со второго аккаунта, повторите сквозной сценарий и зафиксируйте результат. Люди сами заполняют ФИО, фактический вклад и раздел опыта. Публично передаётся очищенный стартовый код с разрешённым демо; внутренний исследовательский ZIP со всеми данными не публиковать целиком.
